# Игровой аддон Anomaly Donation Bridge

Это MO2-ready корень автономного Lua-аддона для S.T.A.L.K.E.R. Anomaly 1.5.3.
Аддон не меняет движок и не заменяет штатные скрипты или конфигурации игры.

## Установка

- MO2: подключите папку `game-addon` как отдельный мод.
- Вручную: скопируйте находящуюся здесь папку `gamedata` в корень игры.

Этот каталог содержит только ядро. `legacy-scripts` оставлены вне `gamedata`
для регрессионных проверок и не должны устанавливаться в игру. Все 25 отдельных
файлов эффектов находятся в папке приложения `effects/gamedata/scripts`; общая
кнопка настроек устанавливает ядро и эффекты. Без файла эффекта ядро не создаёт пресет.

В папке игры должна остаться ровно одна копия каждого скрипта. Файлы вида
`anomaly_donation_bridge_* (2).script`, создаваемые вариантом Windows «сохранить
оба», недопустимы: Anomaly автоматически загрузит их повторно.

Все устанавливаемые файлы находятся в `gamedata/scripts` и используют префикс
`anomaly_donation_bridge_`. `addon.init` не требуется. Для удаления достаточно
удалить эти namespaced-файлы.

## Работа

Аддон автоматически регистрирует `actor_on_update`, подключается только к
локальному pipe `\\.\pipe\AnomalyDonationBridge.v1` и не открывает сетевых
соединений. Протокол v1 использует percent-encoded UTF-8 строки размером не более
16 КиБ. Команды дедуплицируются, выполняются последовательно и возвращают
`executed`, `rejected`, `deferred` или `uncertain`.

Загрузка сохранения и переход уровня не сбрасывают каталог и pipe намеренно.
Если системный канал всё же разорван, приложение может повторно прислать тот же
command ID только при совпадении PID игры; встроенная дедупликация возвращает
прежний результат и не применяет эффект дважды.

После подключения аддон сообщает профиль и возможности движка. Каталог мутантов,
NPC, реальных отрядов, предметов и аномалий строится из текущего объединённого
`system_ini():section_for_each`. Каждая запись локализуется средствами игры,
классифицируется и получает безопасный статус либо причину карантина. Каталог
передаётся атомарным BEGIN/ENTRY/END snapshot с ревизией и SHA-256. Перед каждым
динамическим действием section ID и ревизия проверяются повторно в Lua.

Четыре базовых файла регистрируют `spawn_npcs`, `spawn_mutants`,
`spawn_items` и `spawn_anomaly`. Другие ID доступны после установки
соответствующего отдельного Lua-файла из папки `effects`:

- `add_radiation`, `drop_active_weapon`;
- `spawn_npc_squads`, `spawn_mutant_squads`;
- `spawn_random_hostile_squad`, `spawn_random_mutant_pack`;
- `change_health`, `change_needs`, `change_money`;
- `get_drunk`, `trigger_emission`, `sleep_hours`;
- `remove_equipment`, `damage_equipment`, `drop_random_items`, `teleport_random`;
- `random_active`, `random_all_presets`;
- `use_random_consumable`, `change_player_faction`.

`random_active` и `random_all_presets` являются защитными Lua-регистрациями:
мета-пресеты обязано разрешить Windows-приложение в конкретную обычную команду.
Если мета-ID всё же дойдёт до игры, он будет отклонён.

`use_random_consumable` вызывает штатный `actor:eat`; если сборка предоставляет
перехватчик использования, он также учитывается. `change_player_faction`
выбирает только одну из отмеченных живых группировок `game_relations` текущей
сборки, повторно проверяет ревизию каталога перед изменением и сообщает об этом
в КПК. `spawn_items` умеет выбрать случайное безопасное оружие, броню, шлем или
артефакт из живого каталога, по отдельному флажку активировать первый выданный
экземпляр оружия, добавить совместимые патроны и сообщает в КПК локализованное
название с количеством (с fallback на section ID).

Жажда меняется только через проверяемый адаптер штатного `actor_status_thirst`.
Если модпак заменил внутреннюю реализацию, ненулевое изменение жажды отключается,
не подменяя базовый файл. Сон по умолчанию использует
`ui_sleep_dialog.sleep_forced`; отдельный выключенный по умолчанию чекбокс
включает автономную последовательность сна через движковые функции. Выброс —
штатный `surge_manager`. Реальные squads создаются со штатным составом секции
непосредственно на проверенной навигационной вершине около игрока через
`alife_create` + `create_npc(nil, ...)`, после чего регистрируются в `sim_board`.

Extension API для локальных сборок описан в [EXTENSIONS_RU.md](EXTENSIONS_RU.md).

## Совместимость и безопасность

Основные профили: Anomaly 1.5.3 vanilla, xray-monolith standard и MT-TEST.
На неизвестном движке зарегистрированные действия остаются доступны для теста.
В xray-monolith профиль различается по штатному `get_modded_exes_name()`:
`Modded Exes` и `Modded Exes MT-TEST`. Старый или сторонний бинарник, который
отдаёт только числовую дату `get_modded_exes_version()`, честно обозначается как
`unknown`, потому что по одной дате нельзя безопасно отличить Standard от MT-TEST.
Это не отключает весь мост: непосредственно перед командой каждый обработчик
повторно проверяет свои actor, ALife, каталожные, squad, effector или
навигационные API и безопасно возвращает причину, если конкретный API отсутствует.
Аддон никогда не исполняет текст сообщения или доната через `loadstring`, `dofile`,
консольную команду либо иной remote eval.
