# Подключение DonationAlerts

[← Первый запуск](../README.md#5-подключите-сервис-донатов) · [DonateX](DONATEX_SETUP_RU.md)

Нужны аккаунт DonationAlerts и собственное OAuth-приложение. Ссылка на страницу донатов вида `/r/ваш_код` не заменяет Client ID и Client Secret.

## 1. Создайте OAuth-приложение

1. В ADB откройте **Настройки → Интеграция → DonationAlerts**.
2. Нажмите **«Открыть OAuth-приложения»**, войдите на сайт и создайте приложение.
3. Укажите название, например `Anomaly Donation Bridge`.
4. В поле **URL перенаправления / Redirect URI** вставьте адрес целиком, с последним `/`:

   ```text
   http://127.0.0.1:17871/donationalerts/callback/
   ```

5. Сохраните приложение.

![Адрес возврата для OAuth-приложения](readme/02-oauth-setup.png)

## 2. Подключите аккаунт

1. Скопируйте **ID приложения** в поле **Client ID** программы.
2. Скопируйте **Client Secret** — на сайте он также может называться **«Ключ API»** — в поле **Client Secret**.
3. Поле **«Код аккаунта»** можно оставить пустым. Если указать часть своей ссылки после `/r/`, программа дополнительно проверит, что подключён нужный аккаунт.
4. Нажмите **«Подключить аккаунт»** и разрешите доступ в открывшемся браузере. Предварительно нажимать «Сохранить» не нужно.

**Проверка:** программа показывает имя и код подключённого аккаунта. При несовпадении с указанным кодом обработка отключается.

![Поля подключения DonationAlerts](readme/03-connect-account.png)

## Защита API и хранение доступа

Оставьте включённой **«Защиту DonationAlerts API»**. Она ограничивает HTTP-запросы приложения; новые донаты поступают через WebSocket.

Client Secret и токены хранятся локально с шифрованием Windows DPAPI для текущего пользователя. Не публикуйте их в сообщениях или скриншотах. Оба сервиса можно использовать одновременно: у них отдельные подключения и общая очередь эффектов.

Если авторизация не завершается, проверьте точное совпадение Redirect URI. Не заменяйте `127.0.0.1` на `localhost`, не меняйте порт и не убирайте последний `/`.
